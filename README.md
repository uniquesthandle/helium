# Свойства гелия-4, версия 2 (T = 50–3000 К, P = 10 Па – 100 МПа)

Две реализации одного интерфейса, рассчитанные на теплогидравлические коды реального времени.
Криогенная область (< 50 К) не поддерживается.

| | Вариант A – таблица | Вариант B – аналитическая модель |
|---|---|---|
| Что хранится | одна функция G = ln φ = gʳ/(RT), квадродерево, биквинтические полиномы (C²) | коэффициенты уравнения Гельмгольца (десятки чисел) |
| Свойства | дифференцированием G | дифференцированием Φʳ(T, ρ) |
| Скорость (1 ядро, ВМ) | PT: ~0.1–0.25 мкс, PH/PU: ~0.3–0.7 мкс | PT: ~0.3–0.5 мкс, PH/PU: ~1–2 мкс |
| Размер | 0.06 МБ (115 листьев при tol = 1e-4) | < 1 КБ |
| Эталон нужен | на этапе построения (CoolProp/REFPROP/свой) | на этапе подгонки (`he_fit`) |

Какой выбрать: если у вас есть быстрый доступ к аттестованному эталону только офлайн, а в расчете нужна
максимальная скорость и точное воспроизведение эталона до tol – вариант A. Если важны компактность,
отсутствие файлов данных и гладкость – вариант B (но его точность определяется качеством подгонки класса
уравнения под эталон, `he_fit` печатает остаточные ошибки).

## Файлы

| Файл | Назначение |
|---|---|
| `he_api.h/.cpp` | общий интерфейс `Model`: маски, `PT`/`PH`/`PU`, обращение по T, пакетные вызовы, коды и флаги |
| `he_table.h/.cpp` | вариант A: формат БД (версия, порядок байтов, контрольная сумма), `mmap`, вычисление |
| `he_eos.h/.cpp` | вариант B: уравнение состояния, перенос, загрузка/сохранение коэффициентов |
| `he_ref.h/.cpp` | эталон для построителя: встроенный (= модель B) или CoolProp (`-DUSE_COOLPROP`) |
| `he_table_build.cpp` | программа 1: построение таблицы с адаптивным квадродеревом и контролем |
| `he_calc.cpp` | программа 2: расчет по `PT`/`PH`/`PU` для обоих вариантов |
| `he_fit.cpp` | подгонка модели B под CSV с эталонными данными |
| `he_test.cpp` | автотесты и измерение скорости |

## Сборка и быстрый старт

    make                                   # he_table_build, he_calc, he_test, he_fit
    ./he_table_build -o he_table2.bin --tol 1e-4 --selfcheck 2000
    ./he_test he_table2.bin                # полный набор проверок и тест скорости
    ./he_calc --model table:he_table2.bin --mask T,rho,cp,mu PH 1e7 2.6e6
    ./he_calc --model analytic PT 101325 300
    printf "1e6 1.0e6\n1e6 2e6\n" | ./he_calc --model table:he_table2.bin --mmap --mask T,rho PH -

## Программный интерфейс

    #include "he_table.h"          // или "he_eos.h"
    std::string err;
    auto m = he::TableModel::open("he_table2.bin", err, he::OPEN_MMAP /*| he::OPEN_MLOCK*/);
    he::Hint hint;                 // один объект на поток / расчетный канал
    he::Result r;
    // по (P, T): вычисляются только величины маски
    int e = m->PT(P, T, he::HP_RHO | he::HP_CP | he::HP_DRDP, r, &hint);
    // по (P, H): температура находится итерацией (Ньютон, начальное приближение – предыдущая T из hint)
    e = m->PH(P, H, he::HP_T | he::HP_RHO | he::HP_DRDH, r, &hint);
    // по (P, U)
    e = m->PU(P, U, he::HP_ALL, r, &hint);
    if (e == he::HE_OK) { double T = r.T, rho = r.rho; unsigned fl = r.flags; }

* Маска `HP_*`: T, RHO, CP, CV, U, H, LAM, MU, PR, DUDT, DRDT, DRDU, DRDH, DRDP (всего 14, из них не более 13 за вызов:
  при `PT` температура – вход, при `PH`/`PU` вместо H (U) возвращается T). Невычисленные поля = NaN, `r.computed` – маска вычисленного.
  Зависимости учитываются автоматически (например, для `HP_DRDU` внутри считаются ρ, cp, dv/dT).
* `r.flags`: `FL_LOW_T`, `FL_HIGH_T`, `FL_LOW_P`, `FL_HIGH_P` – точка вне паспортного диапазона, результат – экстраполяция.
  Жесткие границы расчета: T 20–6000 К, P 1 мПа – 1 ГПа; вне них `HE_BAD_INPUT`.
* Коды: `HE_OK = 0`, `HE_BAD_INPUT = -1` (NaN, ≤ 0, вне жестких границ), `HE_NO_SOLUTION = -2` (для (P,H)/(P,U) нет T
  в [20, 6000] К), `HE_MODEL_FAIL = -3`.
* Пакетные вызовы: `PT_batch`, `PH_batch`, `PU_batch` (подсказка передается между точками канала).
* Потоки: `evaluate`/`PT`/`PH`/`PU` не изменяют модель; `Hint` – по одному на поток. Единственное исключение –
  `AnalyticModel`: после изменения коэффициентов через `coef()` вызовите `finalize()` до многопоточной работы.

## Как реализованы пункты рекомендаций

| Пункт | Реализация |
|---|---|
| 1. Один потенциал вместо набора свойств; C² | вариант A хранит G = ln φ; ρ, h, cp, cv, U, dρ/dT, dρ/dP и т. д. – дифференцированием, поэтому тождества выполняются как следствие построения (тест: расхождение с конечными разностями ≤ 1e-10). Биквинтический эрмитов полином – C² внутри согласованных областей; на стыках листьев разных уровней непрерывность выполняется с точностью до ошибки интерполяции (измеренный скачок 9.6e-5 при tol = 1e-4). Вариант B – потенциал Φʳ по построению |
| 2. Аналитическая модель | вариант B: Φʳ = φ_CS(η(T,ρ)) + Σ nᵢ θ^(−tᵢ) r^(dᵢ); перенос – полиномы ln μ₀(T), ln λ₀(T) + поправка Энскога + подгоняемая добавка. `he_fit` подгоняет все коэффициенты линейным МНК под CSV |
| 3. Переменные кода | вызовы `PT`, `PH`, `PU`; T из (P,H)/(P,U) – Ньютон по монотонной h(T) (или u(T)) с защитой скобкой, ≈3 итерации, точность по T ~1e-15 |
| 4. Выход за диапазон | экстраполяция с флагами: по T – разложение Тейлора по ln T (A) или естественное продолжение (B); по P вниз – вириальный закон G ∝ P; по P вверх – Тейлор; статусы вместо аварийного завершения |
| 5. Скорость | коэффициенты полинома хранятся в каждом листе (не пересчитываются); считаются только запрошенные величины; индекс листа за O(1) (равномерная вспомогательная сетка) и кэш последнего листа в `Hint`; `mmap`/`mlock`; пакетные вызовы. Не сделано: структура массивов (SoA) для векторизации |
| 6. Качество | квадродерево (локальное измельчение); в каждом листе 9 контрольных точек по всем 13 выходным величинам; итоговый контроль на 2·10⁵ случайных точек через рабочий API; контроль скачков на стыках; `--selfcheck` проверяет самосогласованность эталона (cp = ∂h/∂T, Максвелл и др.); заголовок БД содержит версию, порядок байтов, размеры структур, контрольную сумму, допуск и название эталона |

Примечание к п. 6: критерием измельчения служит отклонение от эталона по всем выходным величинам; согласованность
обеспечивается самим построением (потенциал) и проверяется (`--selfcheck`, `he_test`), а не используется как критерий измельчения.

## Результаты проверок (встроенный эталон, tol = 1e-4; ВМ с одним ядром)

* Таблица: 103–115 листьев (максимум уровня 3), 0.06 МБ, построение ~0.1–2.5 с.
* Отклонение таблицы от эталона на 200 004 случайных точках: ≤ 9.6e-5 по всем 13 величинам
  (ρ ≤ 2.5e-6, cp ≤ 1.7e-5, μ ≤ 9.6e-5, dρ/dP ≤ 1.2e-5).
* Тождества на конечных разностях (cp = dH/dT, dρ/dT, dU/dT, dρ/dP): p99 ≈ 1e-10 для обоих вариантов.
* Обращение (P,H) и (P,U): |ΔT/T| ≤ 1e-15; в среднем 2.95 итерации, максимум 6.
* Маски: единичная маска дает значение, побитово совпадающее с полной маской; лишнего не вычисляется.
* Защита файла: изменение одного байта, усечение, чужой порядок байтов – обнаруживаются при открытии.
* Синтетическая проверка `he_fit`: «эталон» = модель с измененными на 4 % коэффициентами и двумя дополнительными членами; по 1600 точкам
  подгонки на независимой сетке из 1440 точек: ошибка ρ ≤ 1.8e-5, μ ≤ 3.4e-4, λ ≤ 9.3e-5 (до подгонки до 10 %). Это проверка
  механики подгонки; на реальных данных результат нужно оценивать по печатаемым ошибкам.

## Подгонка под аттестованный эталон (вариант B) и построение таблицы (вариант A)

1. Получите CSV с заголовком `T,P,rho,mu,lambda` (СИ) из аттестованного источника (REFPROP / CoolProp / NIST) на сетке,
   равномерной по ln T и ln P, ≥ 1500 точек, плотнее при T < 100 К и P > 30 МПа; отдельно – независимый проверочный набор.
2. `./he_fit data.csv -o coef.txt` – печатает ошибки модели до и после подгонки. Проверьте их на проверочном наборе.
3. Вариант B: `./he_calc --model analytic:coef.txt ...` или `AnalyticModel::load`.
4. Вариант A: либо `./he_table_build --coef coef.txt` (таблица повторяет подогнанную модель B), либо сборка с CoolProp:
   `make coolprop CP_INC=... CP_LIB=...` и `./he_table_build --tol 1e-4 --step 0.02` (для CoolProp рекомендуется `--step 0.05`).

## Ограничения (важно)

* **Встроенные коэффициенты не аттестованы** (B(T) – по приближенным справочным значениям, вязкость – степенная зависимость).
  Без подгонки/эталона точность относительно реального гелия не подтверждена; в плотной области (T < 100 К, P > 30 МПа)
  и при T > 1500 К возможны отклонения более 1 %.
* Ветка CoolProp (`-DUSE_COOLPROP`) в этой среде не компилировалась и не запускалась.
* Экстраполяция вне паспортного диапазона – инженерная оценка, не расчет; при ожидаемом выходе за T < 50 К нужна отдельная модель.
* Переносные свойства в варианте A – полиномы класса C¹ (производные от них не требуются).
* Примеси в гелии и смеси не учитываются.
* Время расчета измерено на одноядерной виртуальной машине, абсолютные значения на целевом оборудовании будут другими.
